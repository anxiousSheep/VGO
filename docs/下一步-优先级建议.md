| 项 | 内容 |

| 版本 | v0.1 |

## 排序原则

1. **用户可感知**优先于「架构洁癖」：先做关掉应用再打开就能感到差异的项。
2. **信任**优先于「延迟」：教学产品「讲错比不讲更糟」，溯源与校验闭环先于投机优化。
3. **依赖就绪**优先：真实服务已就绪，评估/采集类任务现在才第一次有数据可做。
4. 每项仍遵循「无 Qt 逻辑 + 单测 + 降级回退」的既有约束。

## P0-1 · D3 学习者画像最小闭环（最优先）

> 达成设计文档 §5.4 的验收：「重开应用后画像仍在」「它记得我」——这是现有版本被暴露的最强短板，也是四项里唯一「关掉再打开就有强烈差异感」的。

| 任务 | 现状 | 投入 | 产出 |
|---|---|---|---|
| **D3.6 教练记忆注入 prompt** | `LearnerModel::coachMemory()` 已就绪，只差注入 | 半天 | `http_conversation`/`template_conversation` 注入「你最近在打劫上吃亏」类记忆 |
| **D3.3 LearnerStore 持久化 + 隐私三件套** | `serialize/deserialize` 已就绪，缺 Qt 落盘 | 半天–1 天 | `ui/model/LearnerStore` jsonl 落盘 + 开关/导出/清空（沿用 DPAPI 密钥机制） |
| **D3.2 blunder 采集** | `MoveEvaluator` + `isBlunder` 已有，`maybeWarnBlunder` 已接 UI | 半天 | UI 空闲低优先级异步 what-if → 喂弱项向量 |

**为什么先做这一组**：三者互为闭环——采集（D3.2）产出数据，持久化（D3.3）跨局累积，注入（D3.6）让教练真正「记得」。单做任何一项都半途而废，合起来才是 D3 的完整价值。真实服务已可用，blunder 采集首次有真实 KataGo 数据可依赖。

**暂缓**：D3.4 动态难度（依赖 D3.2/D3.3 的数据支撑，且要谨慎保留手动 override）、D3.5 复习队列（「今日一题」入口依赖题源，先不做 UI）。

## P0-2 · D2.4 证据溯源 + D5.6 可观测

> D2 的校验闸门（D2.3）已上线，但用户还看不到「为什么可信」；溯源是把它变成「每句可 hover 看来源、一键跳 PV」的信任分水岭。

| 任务 | 现状 | 投入 | 产出 |
|---|---|---|---|
| **D2.4 证据挂载 hover 溯源 + 跳 PV** | `ClaimVerifier` 已产出 `source`，缺 UI | 1 天 | `ChatPanel`/`GobanWidget` hover 显示来源 + 跳对应 PV |
| **D5.6 可观测 trace 面板** | `positionHash`/`traceToJsonl` 已就绪，缺接线+面板 | 1 天 | 落盘 `agent_trace.jsonl` + 本地面板查看 `{position hash, route, latency, verify, model}` |

**为什么第二组**：D2.4 完成 D2 的「可以信」；D5.6 的 trace 既反哺调试，又直接产出 D2.5「坏样本回收」所需的证据，为后续 D4 评估闭环铺路。

## P0-3 · D5.4 并发池 + D5.2 投机预生成

> 设计文档 §1.1 明确「讲解与 KataGo 分析串行」「异步竞态靠 `generation_` 打补丁」。这一组是「快 + 稳」的最后一块。

| 任务 | 现状 | 投入 | 产出 |
|---|---|---|---|
| **D5.4 KataGo 分析并发池 + 优先级队列** | 现状零散 `generation_` 补丁 | 1–2 天 | 正本清源：消除提问 vs 形势分析互相 cancel |
| **D5.2 投机预生成** | 无 | 1–2 天 | AI genmove 期间并行预跑讲解，position hash 缓存，落子瞬间呈现 |

**为什么第三组**：价值高但复杂、风险集中，必须在 P0-1/P0-2 稳定之后再做，否则难以回退定位。设计文档 §8 也建议「D1/D2 稳定后再做『老 App vs 新版』对比评测」。

## P1 · D4 评估闭环 + 自进化（持续）

> 真实服务已可用，是建立 golden 集的最佳时机——L10「持续优化 Skills」从此有度量与完成标准。

| 任务 | 产出 |
|---|---|
| **D4.5 golden Q&A 集 + D5.7 纳入 CTest** | skill-on/off 对比指标表，release gate = 回归通过 |
| **D4.6 自进化 + D4.7 版本回滚/热更加固** | pending 区 + 一键采纳；设置页显示「上次评分 0.71」 |

**为什么最后**：评估闭环需要前几批沉淀的真实问答作为 golden 样本；在样本充足前先建空集是无源之水。

## 暂缓项（明确不做或等依赖）

| 项 | 理由 |
|---|---|
| D1.7 `sgf_lookup_position` | 依赖 L5（SGF 标准棋谱读写）落地 |
| D4.2 渐进式披露 | 现有 skill 都很小（< 1KB），frontmatter/body 分离的收益有限 |
| D5.3 模型路由 | 需先有第二个可路由的模型（轻模型意图/工具 + 强模型讲解） |
| D5.5 的「每局/每日 token 上限」 | 单次 `max_tokens` + 超时已上线；总账计费需先有 trace 数据支撑 |

## 一句话总结

**先做 D3（它记得我）→ 再做 D2.4+D5.6（可以信、可调试）→ 后做 D5.2/D5.4（快且稳）→ 最后 D4 评估闭环（质量随时间变好）。**

对应长期任务清单：本建议落地的是 L11（已升格 P0，D2.4 补溯源）、L10（D4 评估闭环给度量）；D3 为新增能力；D5.4 覆盖历史「在途分析取消重启」竞态修复的正本清源。
