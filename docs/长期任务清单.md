## 2. 分项说明

### 2.1 引擎强度与真实性

#### L1 — 19 级难度真实 KataGo 标定 🧪
- **现状**：`strengthForLevel(1..19)` 映射已实现；`tools/calibrate_strength.cpp` 用离线引擎做过相邻档对弈 spike（单调递增已初步验证）。但「职业段 = 标准模型 + visits」的强度锚点未与真实 KataGo 对拍。
- **目标**：在装有 KataGo 的环境中，让相邻档位互相对弈（或与 KataGo 内置段位 / 公开等级分对标），校到「强度单调递增、相邻档有可感知差距」。
- **产出**：固化的最终映射表（更新 `ai/strength.cpp` 与 `docs/技术路线-选型与任务计划.md` §2.2）。
- **阻塞解除条件**：需真实 KataGo + 标准 / HumanSL 模型（依赖 L13）。

#### L2 — 更细的难度标定 ⬜（P2）
- **现状**：19 级为初值映射，职业偶数段等细节靠 search-blend 插值，插值后的真实强度未标定。
- **目标**：在 L1 基础上细化档位、校验 search-blend 插值效果，使每一档都有可感知差距。

---

### 2.2 死活与教学深度

#### L3 — 眼形 / 要点死活求解（N6）⬜（P1）
- **现状**：`LifeDeathAnalyzer`（`ai/lifedeath.*`）目前用 ownership 判死 + 防守搜索，只能给「能活 / 不能活 + 无救活之手」的诚实结论；更细的「眼位太小 / 要点被占」未实现。
- **目标**：局部几何死活题求解——算眼位、找 vital point（要点），或接入围棋专用模型辅助。
- **产出**：`lifedeath.*` 深化 + 单测；让「为什么做不活」能指出具体要点。
- **依赖**：KataGo ownership 数据（L13）。

#### L4 — 死活题生成与求解 ⬜（P2）
- **目标**：基于 L3 的能力生成死活题，供用户练习，并与 Skills 联动。

---

### 2.3 棋谱与复盘生态

#### L5 — SGF 标准棋谱读写 ⬜（P1）
- **现状**：当前仅有自定义 `.vgo` 纯文本格式（`src/ai/record.*`），不兼容标准 SGF。
- **目标**：读写标准 SGF（FF[4]）棋谱，支持导入 / 导出主流棋谱，打通与外部棋谱库的互操作。

#### L6 — 让子对弈 ⬜（P1）
- **目标**：支持让子局（handicap），在 `GameSetup` 中扩展让子数与让子点布置，难度与让子联动。

#### L7 — 复盘分支回放 ⬜（P1）
- **现状**：复盘模式已支持 `.vgo` 逐手回看 + 从任意局面试下，但无「分支树」。
- **目标**：复盘时支持分支记录与回放（试下的变化可保存为分支）。

#### L8 — 叙事级终局复盘 ⬜（P2）
- **现状**：M3b.3 已实现「终局汇总本局恶手」，但非叙事级。
- **目标**：终局后按转折点生成叙事性复盘（在哪几手逆转 / 关键失误），供学习回看。

---

### 2.4 LLM 与交流质量

#### L9 — LLM 半提示完整实现 🧪（P1）
- **现状**：`req.hint` 已有模板方向提示 + HTTP 不泄露坐标；与真实 LLM 的「只给方向、不给坐标」联调未完整验证。
- **目标**：接入真实 LLM 后验证半提示在各类问题（死活 / 落点 / 形势）下都能只给方向。

#### L10 — 持续优化 LLM 模型的 Skills 🔁（P0，本次新增）
- **背景**：通用 LLM 对围棋专业度不足，项目用 `resources/skills/*.md`（counting / ko / life-death / move-quality / terms 五个知识包）按问题类型注入 system prompt。这些知识包的质量直接决定 LLM 讲解的专业度与可信度。
- **为什么是长期任务**：围棋领域知识没有「一次性写完」的终点——随着真实 LLM 实测（L13）暴露问题、新的问题类型被识别、不同模型（Ollama / DeepSeek / Qwen 等）对提示词敏感度不同，知识包需要**持续迭代**。这不是一次性交付，而是随项目演进的持续工作。
- **长期目标**：
  1. **迭代现有知识包**：根据真实 LLM 输出复盘，修正术语、补充边界 case、优化 prompt 措辞。
  2. **扩充新知识包**：逐步覆盖 布局（定式 / 开局）、官子、手筋、形势判断细则、让子局常识等（新增 `resources/skills/*.md` 并同步 `SkillRegistry` 命中规则）。
  3. **加入 few-shot**：给关键知识包补少量示例问答，提升小模型（本地 Ollama 7B 级）的稳定输出。
  4. **多模型适配**：针对不同 provider 的指令遵循能力，微调 system prompt 的约束强度与长度。
  5. **诚实性护栏**：持续校验知识包不诱导 LLM 编造坐标 / 目数，守住 Grounding 契约。
- **产出**：`resources/skills/*.md` 的持续更新 + 实测记录（可在 `docs/` 下维护一份 skills 迭代日志）。
- **依赖**：真实 LLM 接入（L13）。

#### L11 — Grounding 校验器（输出 vs facts 回退）⬜（P2）
- **现状**：为简化，当前以「模板诚实条款」约束 LLM，未做输出与 facts 的自动比对。
- **目标**：实现轻量校验器，输出中的坐标 / 目数 / 胜率与 `GroundedFacts` 不符时自动回退纯模板文案。

#### L12 — CommentaryPolicy（话痨 / 成本控制）⬜（P2）
- **现状**：策略字段已预留，未接入。
- **目标**：只对关键手 / 大失误 / 提问讲解，控制 LLM 调用成本与话痨。

### 2.5 集成与实测

#### L13 — 真实 KataGo / LLM 集成实测 🧪（P0）
- **现状**：KataGo GTP 客户端、LLM HTTP 客户端、SSE 流式、模型自安装均已实现并通过单测（55+ 测试通过），但**未与真实 KataGo / 真实 LLM 端到端对拍**（本机无 KataGo）。
- **目标**：在真实环境验证 ① KataGo 握手 / 分析 / ownership / humanSLProfile 档位；② 各 LLM 预设（Ollama / DeepSeek / Qwen / Kimi / 智谱 / OpenAI / OpenRouter）的真实回答质量与诚实性；③ 一键供给与自检流程端到端跑通。
- **产出**：实测记录 + 偏差修复；解除 L1 / L3 / L9 的阻塞。

#### L14 — 模型 / KataGo 升级检查 ⬜（P2）
- **现状**：KataGo 版本固定 v1.18.1（OpenCL / Eigen）；升级检查（查 GitHub latest、提示更新）作为后续项。
- **目标**：启动时（或设置页）检查 KataGo / 模型新版本并提示升级。

## 3. 维护约定

1. **单一事实来源**：本清单是长期任务的汇总入口；各任务的详细设计仍以上游文档为准，状态以本文为准。
2. **同步更新**：完成或变更某项后，同步更新本文状态列与对应上游文档。
3. **优先级**：P0（阻塞 / 持续）→ P1（计划内）→ P2（愿景）。
4. **持续任务**：L10（Skills 优化）为 🔁 类型，无固定终点，建议随每次真实 LLM 实测（L13）迭代一轮。
