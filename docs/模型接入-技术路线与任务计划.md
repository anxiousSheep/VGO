## 1. 设计原则

1. **零手工优先**：能自动下载、自动选变体、自动生成配置的，不让用户填。
2. **稳定降级**：任何一步失败都不阻塞对局，自动回退现有 `FallbackEngine` / `TemplateConversation`，并明确告知原因。
3. **密钥不落明文**：API key 用 Windows DPAPI 加密后落盘，UI 打码。
4. **真实可验**：接入完成后能「自检」证明 KataGo / LLM 真的可用，而非仅「配置写进去了」。
5. **延续既有规范**：`src/ai/` 保持无 Qt、无 I/O；本阶段新增的下载/供给/密钥全部是 Qt/平台层，不污染核心。

## 2. 技术选型总览

| 维度 | 选型 | 说明 |
|---|---|---|
| 下载传输 | `QNetworkAccessManager` + `QNetworkReply` | 复用 Qt6::Network |
| 断点续传 | HTTP `Range`（`Accept-Ranges` 支持时） | 模型文件大，支持中断恢复 |
| 下载源选择 | 官方 + 镜像**双源按稳定性选择** | 见 §3.2 |
| 解压 | Windows 系统 `Expand-Archive`（PowerShell） | 不引入第三方 zip 库 |
| GPU 检测 | 动态探测 OpenCL / CUDA | 见 §3.3 |
| 配置生成 | 程序内写最小 GTP 配置 | 不要求用户手写 |
| 完整性校验 | SHA-256（与清单比对） | 下载失败/篡改可感知 |
| 密钥存储 | Windows **DPAPI**（CryptProtectData）加密，密文落盘 | 见 §3.5 |
| 配置目录 | `QStandardPaths::AppDataLocation` | 从 exe 旁迁到用户数据目录 |
| LLM provider | OpenAI 兼容协议 + 预设表 | 本地 Ollama 优先 |
| 模型清单 | 内置 `models.json` 清单（可热更） | 模型可增删、URL 可改不重编译 |
| 测试 | 自研框架 + CTest；下载/供给用桩与本地 HTTP 测 | 见 §4 |

## 3. 详细设计

### 3.1 配置与目录迁移

- 配置从 `applicationDirPath()`（exe 旁，可能只读）迁到 `QStandardPaths::AppDataLocation`（如 `%APPDATA%/VGO/`）。
- 拆两份：
  - `config.json`（公开）：KataGo 路径/版本/变体、模型清单、LLM provider/base_url/model 名、UI 偏好。
  - `secrets.json`（私密）：仅存 DPAPI 加密后的 api_key 密文（见 §3.5）。
- 首次启动：若无配置目录，创建之；读旧 `vgo_config.json` 迁移一次（向后兼容）。
- 现有 `AppConfig` 只读不变，`ModelManager` 负责读写新结构并对外提供快照。

### 3.2 下载源：官方 + 镜像，按稳定性选择

- 每个可下载资产（binary / 模型）在清单里定义 `sources[]`：**官方在前、镜像在后**，每项含 `url`、`size`、`sha256`。
- `Downloader` 的选源算法（MVP，够用且可解释）：
  1. 按「上次成功源优先」排一次序（记忆化），再按清单顺序。
  2. 逐个源尝试：连接超时 `8s`、首字节超时 `15s`；下载中若前 64KB 内停滞超 `10s` 视为不稳定，放弃换下一源。
  3. 成功并 SHA-256 校验通过 → 记录该源为 `lastGood`。
- 效果：官方（GitHub）慢/被墙时自动落到镜像，反之亦然；网络抖动不重试死磕一个源。
- 断点续传：目标文件已存在部分时，带 `Range: bytes=N-` 续传；服务器不支持则整文件重下。

### 3.3 KataGo 自动供给

- **变体选择**（自动，默认不打扰用户）：
  - 检测到 OpenCL → 用 `opencl`（快，兼容广）。
  - 无 GPU/无 OpenCL → 用 `eigen`（纯 CPU，**一定可用**，保底）。
  - CUDA 仅作「高级」手动选项（依赖 CUDA runtime，默认不自动选）。
- **下载 + 解压**：binary 走 §3.2 双源下载 → `Expand-Archive` 解压到 `<data>/katago/<version>/`。
- **配置生成**：程序内写 `<data>/katago/gtp.cfg`（最小配置：`logAllGTPCommunication=false`，其余用 KataGo 默认），不要求用户手写。
- **版本与升级**：`config.json` 记已装 `version + variant`；启动时（节流，≥24h 一次）或设置页手动查 GitHub latest，有新版提示「更新」。
- **校验**：解压后对 binary 做 SHA-256；不匹配则删除重下并提示。

### 3.4 模型：用户自选安装

- `models.json` 清单内置三类（每类含官方+镜像 URL、大小、SHA-256、用途）：

| id | 名称 | 用途 | 大致大小 |
|---|---|---|---|
| `b18c384nbt` | 标准模型 | 职业段（visits）+ 普通对弈 | ~100MB 级 |
| `b18c384nbt-humanv0` | 人类风格模型 | 新手/业余段（humanSLProfile）真实性 | ~100MB 级 |
| `b6c96` | 快速小模型 | 低配机/秒回，强度弱 | ~20MB 级 |

- 设置页「模型」区块列出三类，各带「安装/删除/大小/说明」；**用户勾选安装哪个**。
- 缺模型时的降级：职业段（12–19）缺标准模型 → 用已装模型 + visits，仍可用；业余段（1–11）缺 humanv0 → 提示「装人类风格模型可获更真实的业余段棋力」，临时用标准模型 + visits 近似。
- 清单可随版本热更（本地内置一份兜底，联网时可选拉新清单）。

### 3.5 密钥安全（DPAPI）

- `KeyStore` 封装 `CryptProtectData` / `CryptUnprotectData`（`CRYPTPROTECT_UI_FORBIDDEN`，用户作用域）。
- api_key 明文仅在内存，落盘为 base64(密文) 存于 `secrets.json`。
- UI 一律打码（`••••尾4位`）；日志/调试**永不输出 key**。
- 换机器/换 Windows 用户后 DPAPI 无法解密 → 检测到解密失败提示「密钥需重新输入」（符合预期，不崩溃）。

### 3.6 LLM 接入（本地优先 + 云预设）

- 预设表（全部 OpenAI 兼容，复用现有 `HttpConversationService`）：

| id | 名称 | base_url | 默认 model | 需 key |
|---|---|---|---|---|
| `ollama` | Ollama（本地） | `http://localhost:11434/v1` | 自动检测 | 否 |
| `deepseek` | DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` | 是 |
| `qwen` | 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` | 是 |
| `kimi` | Moonshot/Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` | 是 |
| `zhipu` | 智谱 | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` | 是 |
| `openai` | OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` | 是 |
| `openrouter` | OpenRouter | `https://openrouter.ai/api/v1` | 用户选 | 是 |
| `custom` | 自定义 | 用户填 | 用户填 | 视情况 |

- **本地 Ollama 优先**：`GET http://localhost:11434/api/tags` 自动发现本机模型填入下拉；未装 Ollama 时给「去官网安装」链接（零 key、零成本、隐私好）。
- **测试连接**：发一条 `"只回复 OK"` 的极小请求，展示成功/超时/401（key 错）/连接失败，人话提示。

### 3.7 前置修复：HumanSL 运行时下发

- `KataGoEngine` 当前只 `kata-set-param maxVisits/temperature`，**未下发 `humanSLProfile`**，导致 19 级里业余段「真人档位」实际不生效。
- 修复：`StrengthParams.human_profile` 非空（业余段/新手）时，`genmove` 前追加 `kata-set-param humanSLProfile <rank>`；职业段（空）则只走 visits。
- 这是 M3a.9 映射真正落地的**前置条件**，纳入本阶段 P0。

### 3.8 状态反馈与自检

- 主窗口状态栏常显「当前引擎 / 当前 LLM」：如 `KataGo v1.15 (OpenCL) · DeepSeek`；降级时显 `离线引擎 · 本地模板`，失败原因可 hover。
- 设置页「自检」：
  - KataGo：`protocol_version`（应回数字）、`boardsize 19`（应回 `=`）——证明进程能握手。
  - LLM：§3.6 测试连接。
- 自检结果给**人话诊断**（版本、耗时、失败在哪一步），不是报错码。

## 5. 依赖顺序与验收

**关键路径**：`M5.0（HumanSL 前置）→ M5.1（配置迁移）→ M5.2（密钥）→ M5.3（下载器）→ M5.5（KataGo 供给）→ M5.6（模型）→ M5.7（LLM）→ M5.8（设置页）→ M5.9（状态/引导）`。

**验收标准**：
- 全新机器首次启动 → 引导页 → 点「安装 KataGo」→ 自动选变体、下载、解压、生成配置，完成后能人机对弈。
- 设置页可选装 标准/人类风格/小模型，装删即时生效，缺失时对局自动降级并提示。
- 选任意预设 + 填 key → 「测试连接」能返回真实回复；key 落盘为 DPAPI 密文，UI 打码。
- 官方源不可用时自动切镜像下载成功（可断网模拟验证）。
- 状态栏能看出当前引擎/LLM 与失败原因；HumanSL 档位经 `humanSLProfile` 真正生效。

**衔接**：本阶段落地后，`M3a.10`（难度标定）与 `M0.1`（KataGo spike）的「无 KataGo」阻塞即解除。

## 6. 与已有文档的偏差/衔接记录

| 项 | 原设计 | 本阶段决定 | 说明 |
|---|---|---|---|
| KataGo 来源 | 用户手动下载配置 | 一键供给（官方+镜像双源） | 见 §3.2/§3.3 |
| 模型 | 固定 `b18c384nbt-humanv0` | 用户自选（标准/人类/小） | 见 §3.4 |
| 密钥 | `vgo_config.json` 明文，不入库 | DPAPI 加密 `secrets.json` | 见 §3.5 |
| 配置目录 | exe 旁 | 用户数据目录 | 见 §3.1 |
| humanSLProfile | 预留未下发 | 运行时下发（M5.0） | 见 §3.7 |
| LLM 默认 | 未定 | 本地 Ollama 优先 + 云预设 | 见 §3.6 |
| 断点续传 | HTTP Range 续传 | 整文件重下 + `.part` 原子落盘 | 简化；失败换源重下，见 §3.2 |
