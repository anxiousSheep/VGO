## 2. 难度 ↔ KataGo 对齐（19 级）

19 级难度按现实棋力从弱到强：**新手（1）→ 业余 1–9 段（2–10）→ 职业 1–9 段（11–19）**。用两种引擎来源对齐，遵循「真实性优先」。

### 2.1 对齐原则

| 段位区间 | 引擎来源 | 档位 | 真实性 |
|---|---|---|---|
| 新手 + 业余段（1–10） | HumanSL 模型 `b18c384nbt-humanv0` + `humanSLProfile` | `rank_20k`、`rank_1d`…`rank_9d` | 档位名即段位，相对强度可信 |
| 职业 1 段（11） | HumanSL 顶档 或 标准模型 | `rank_9d` 或 ~1 visit | HumanSL 上限 ≈ 职业初段 |
| 职业 2–9 段（12–19） | 标准模型 + 递增 visits | ~8 … 满强度 | 相对强度锚点，非段位标定 |

### 2.2 初值映射表（待标定）

| 序号 | 标签 | 引擎 | 参数（初值） |
|---|---|---|---|
| 1 | 新手 | HumanSL | `rank_20k`（代表级位段），visits=1，满温 |
| 2 | 业余1段 | HumanSL | `rank_1d` |
| 3 | 业余2段 | HumanSL | `rank_1d`（相邻取弱）或 search-blend 插值 |
| 4 | 业余3段 | HumanSL | `rank_3d` |
| 5 | 业余4段 | HumanSL | `rank_3d`（相邻取弱）或 search-blend |
| 6 | 业余5段 | HumanSL | `rank_5d` |
| 7 | 业余6段 | HumanSL | `rank_5d`（相邻取弱）或 search-blend |
| 8 | 业余7段 | HumanSL | `rank_7d` |
| 9 | 业余8段 | HumanSL | `rank_7d`（相邻取弱）或 search-blend |
| 10 | 业余9段 | HumanSL | `rank_9d` |
| 11 | 职业1段 | HumanSL/标准 | `rank_9d` 或标准 ~1 visit |
| 12 | 职业2段 | 标准 | ~8 visits |
| 13 | 职业3段 | 标准 | ~30 visits |

| 18 | 职业8段 | 标准 | ~10000 visits |
| 19 | 职业9段 | 标准 | 满强度（100k+，超人类） |

### 2.3 真实性约束（必须遵守）

1. **HumanSL 覆盖上限**：HumanSL 模型只覆盖约 20k~业余 9 段/职业初段，**没有职业高段的「人类模仿」档位**；职业 2–9 段只能用标准引擎搜索预算近似。
2. **超人类下限**：标准 KataGo 满强度是超人类（强于任何人类职业 9 段），故「职业 9 段」是**保守标签**。
3. **档位粒度**：HumanSL 为 2 级一档（…,2k,1d,3d,5d,7d,9d），业余偶数段需在相邻档间用 **search-blend**（`P ∝ humanPrior × exp(utility/τ)`，τ 递减）插值；插值后的真实强度需标定。
4. **离线降级**：`FallbackEngine`（无 KataGo）是简单启发式，强度上限≈业余低段；选择职业段但未接 KataGo 时，须明示「离线引擎强度有限，接入 KataGo 才能达到对应段位」。

### 2.4 标定任务（保证真实性）

新增 spike：让相邻档位互相对弈（或与 KataGo 内置段位/公开等级分对标），校到「强度单调递增、相邻档有可感知差距」，产出最终映射表并固化为 `strengthForLevel(1..19)`。

**已完成**：`M0 → M1 → M2 → M3a → M5 → M6 → N1 → N2 → N3 → N4 → M3b → M4 → N5`（模型接入与自安装、Grounding、真实 KataGo/LLM 实测、讲解增强、棋盘演示、流式、Skills、教学增强、打磨）。

- 「新对局…」弹出对话框，可一次选定 模式/大小/执子/难度，局内无法再改。

## 6. 讲解增强与演示（N 系列）—— 选型与任务计划

> 上游设计：`docs/可交流模式-讲解增强与演示-设计.md`。目标：让 LLM 能答「为什么这步不好 / 做不活」等深层问题，并支持棋盘演示、流式讲解、Skills 知识注入。

### 6.1 技术选型（新增，其余沿用 §1）

| 维度 | 选型 | 说明 |
|---|---|---|
| 落点质量评估 | what-if：棋盘副本 + 复用 `kata-search_analyze` | 无新依赖；产出胜率/目数 delta |
| 死活判定 | ownership 判死（复用 M6.3 `deadStones`）+ 确定性防守搜索（纯函数） | 无 LLM、可单测；眼形/要点后置 N6 |
| 问题分类 | 扩展 `classifyQuestion`：拆出 `MoveQuality` / `LifeDeath` | 纯函数 |
| 变化图 | `Variation` 纯数据结构（无 Qt）+ GobanWidget 演示态渲染（手数编号） | 复用棋盘渲染，不污染真实对局 |
| 演示「权威 AI 后续」 | 复用 `analysis_engine_`（与形势判断同源，同一强度档位） | 与形势判断同源 |
| LLM 流式 | `QNetworkReply` 增量读取（readyRead）+ 行级 SSE 解析 | 复用 QNetworkAccessManager，不引入 QHttp |
| Skills | `Skill`/`SkillRegistry`（纯数据，`ai/`）+ JSON 数据文件热更 + 内置默认 | 核心无 Qt；按 QuestionClass 注入 system prompt |
| 逐步确认状态机 | `VariationController`（无 Qt，可单测） | 落子→讲解→确认→下一步 |

### 6.3 依赖顺序与验收

**关键路径**：`N1 → N2 → N3`（✅ 已全部完成）；`N4` 与 N1 并行（✅）；`N5` 收尾（✅）；`N6` 长期。

**N1 验收**：能答「为什么这步不好」（含胜率/目数变化的量化答案）与「为什么做不活」（指出哪块棋 + 「无救活之手」诚实结论），不再统一回「不知道」。

**N2 验收**：可「固定前几步 + 权威 AI 后续」演示，逐手确认/回退/退出，不污染真实对局。

**N3 验收**：讲解随落子流式呈现；LLM 未接时回退模板文本。

**N4 验收**：对应问题自动加载匹配 Skill，知识可热更。
