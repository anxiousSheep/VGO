## 1. 技术选型总览

### 1.1 选型决策表

| 维度 | 选型 | 理由 |
|---|---|---|
| 语言/构建 | C++17 + CMake + MSVC 2022（沿用） | 不引入新工具链 |
| UI | Qt 6 Widgets（沿用） | 已有；`Qt6::Network` 同时覆盖 HTTP |
| **KataGo 接入** | 本地子进程 + **GTP over stdio**（`QProcess`） | 官方标准接口，无网络、低延迟、可取消（`stop`） |
| KataGo 模型 | `b18c384nbt-humanv0.bin.gz`（人类风格） | 支持弱棋标定与人类式落子，见 §3.1 |
| 强度标定 | `humanSLProfile` + `temperature` + `humanPolicy` 采样 | 官方推荐的人类式落子方式 |
| 分析命令 | `kata-analyze`（`includeOwnership`/`includePolicy`） | 一次拿到胜率/目数/归属/主变化，供 Grounding |
| **LLM 接入** | 抽象 `ConversationService` + HTTP + **SSE 流式**（`Qt6::Network`） | 可插拔 provider，避免第三方 C++ HTTP 库 |
| 默认 provider | **Anthropic Claude**（Q&A 用 `claude-sonnet-5-5`，自动解说用 `claude-haiku-4-5`） | 中文表达与教学能力最佳；流式原生支持 |
| 备用 provider | **OpenAI 兼容协议**适配器（Ollama / llama.cpp / DeepSeek / Qwen 等） | 覆盖中国区访问与本地/离线部署，见 §3.3 |
| JSON 解析 | Qt `QJsonDocument`（Qt6::Core 自带） | 零额外依赖 |
| 异步 | 纯逻辑核心无 Qt；I/O 适配器用 `QProcess`/`QNetwork` + 跨线程信号槽 | 保证 `src/ai` 核心可单元测试 |
| 配置 | `vgo_config.json` + 环境变量注入 API key | 路径/模型/provider 集中管理；密钥不入库 |
| 测试 | 沿用自研框架 + CTest；`NullEngine`/`EchoConversation`/mock provider 桩 | 与现有 `tests/` 一致 |

### 1.2 KataGo 关键接口（已核实）

- `kata-analyze` 输出 JSON：`moveInfos[]`（`move`/`visits`/`winrate`/`scoreLead`/`prior`/`utility`/`order`/`pv`/`ownership`）、`rootInfo`（`winrate`/`scoreLead`/`visits`/`currentPlayer`）、`ownership`（长度 = 宽×高，行优先从左上角 A19 到右下角，取值 -1..1）。
- 强度：`humanSLProfile`（如 `preaz_30k`…`preaz_9d`，约 30 档）+ `temperature`（全温=1.0 最像人）；落子从 `humanPolicy` 按概率采样，`maxVisits=1` 即够用。
- 弱棋「过早虚着」修正：>50 visits 检测，若 order 0 是虚着则虚着，否则从 `humanPolicy` 排除虚着后采样。
- 取消/参数热调：GTP `stop`、`kata-set-param`。

### 1.3 强度映射（初值，M0 标定）

| level | humanSLProfile | temperature | 定位 |
|---|---|---|---|
| 1–2 | preaz_30k / preaz_20k | 1.2 | 完全新手 |
| 3–4 | preaz_15k / preaz_10k | 1.1 | 入门 |
| 5–6 | preaz_5k / preaz_1k | 1.0 | 中级 |
| 7–8 | preaz_1d / preaz_3d | 0.9 | 较强 |
| 9–10 | preaz_5d+ / 满搜索 | 0.8 | 强 |

> 具体档位名以 M0 spike 实测为准；本表只锁定「level → profile + temperature」的映射结构。

## 2. 技术路线

### 2.1 分层（延续设计文档的「无 Qt 核心 + Qt 适配器」）

```
src/go/                     现有规则引擎（不动）
src/ai/                     纯逻辑核心，无 Qt、无 I/O，可单元测试
  analysis.h                Analysis / MoveCandidate / OwnershipMap / Variation
  strength.h                level → 参数映射
  sgtp.h/.cpp               GTP 消息编解码 + kata-analyze JSON → Analysis（纯函数）
  explain.h/.cpp            FactExtractor：Analysis → GroundedFacts
  conversation.h            ConversationService 接口 + 请求/回复类型
  session.h/.cpp            AIMatchController 状态机（回调对外，无 Qt）
src/ai/engine_kata/         Qt 适配层：QProcess 承载 KataGo（启动/同步/分析/取消/重连）
src/ai/conversation_http/   Qt 适配层：QNetwork + SSE 流式 + Claude/OpenAI 兼容 provider
src/ui/                     扩展：ChatPanel、AiWorker(线程桥)、GobanWidget 叠加层、MainWindow
tests/                      扩展：test_sgtp / test_explain / test_conversation / test_session
```

### 2.2 端到端数据流

```
用户点击 → Game::play(合法校验) → AIMatchController.onHumanMove
   ├─(player 角色) KataGo humanPolicy 采样 → AI 落点 → Game::play 复验 → 刷新棋盘（快路径）
   └─(coach 角色) kata-analyze(高 visits) → Analysis → FactExtractor → GroundedFacts
           ├─ 纯模板解说（无 LLM 时）
           └─ ConversationService(SSE 流式) → 解说/回答 + 溯源 + 棋盘高亮
```

## 3. 关键技术决策

### 3.1 Player / Coach 双角色（同进程双模式）

一个 KataGo 进程承担两种角色，避免两份算力：

- **Player（落子）**：`humanSLProfile` + `temperature` + `humanPolicy` 采样，产出「像这个段位的人」的落子。
- **Coach（解释/形势）**：`kata-analyze` 用较高 visits（如 100–400）产出**客观**胜率/目数/归属/主变化，供 Grounding 与提问。

**诚实性处理**：当弱棋（Player）下出明显坏棋时，Coach 的客观分析会说「这手掉了胜率」。解说因此分两档：
1. 「我下这里是想……」（Player 视角，从 board diff 抽结构事实）。
2. 「不过这手并不理想，更稳的是 Y」（Coach 视角，仅当开启教学提示时）。

两者都锚定 facts，不冲突、不编造。此张力在 M0.1 用一个小原型确认。

### 3.2 Grounding（防幻觉）落地方式

- LLM 输入 = **facts 底稿**（结构化 `GroundedFacts`）+ 用户问题 + 人设，**不给裸棋盘让 LLM 自由发挥**。
- 输出要求带 `fact_id` 溯源；模板内置「诚实条款」（无对应事实就说「需要再算」）。
- 轻量校验器：抽取 LLM 输出中的坐标/数字与 facts 比对，不一致回退纯模板文案。

### 3.3 中国区访问与降级

- 默认推荐 Claude（质量最佳）；因国内直连受限，`OpenAI 兼容适配器`为一等公民：可指向本地 Ollama / llama.cpp，或国内可用模型（DeepSeek / Qwen）。
- 降级链：LLM 不可用 → 纯模板解说（facts 直出）；引擎不可用 → 明示「AI 离线」，回退双人摆棋。

## 5. 里程碑验收与依赖顺序

**关键路径**：`M0.1 → M0.2 → M0.3 → M0.4/M0.5 → M0.6 → M0.7 → M1 → M2 → M3 → M4`

- **并行机会**：M0.2/M0.5（接口与数据模型）可与 M0.1 spike 并行；M1.1（事实抽取）只依赖 M0.3 的编解码，可与 M0.4–M0.7 并行。
- **里程碑验收**：
  - M0：能下一整局人机对弈，难度可调。
  - M1：AI 每手落子后有一条**可信**模板解说。
  - M2：能自然语言提问并流式回答，回答可溯源、有校验回退。
  - M3：六类交流原语齐全。
  - M4：性能达标，双击可运行，文档齐全。
