## 1. 概述

### 1.1 定位

在现有「双人对弈 / 摆棋」基础上新增第三种模式：**人类执一方，AI 执另一方**。

与传统人机对弈的区别是——AI 不只「下棋」，还**解释自己**：落子后主动说一句「为什么」，并且人类可以随时**用自然语言提问**（「你为什么下这里」「我该下哪」「我现在优势吗」），AI 给出**有据可依、新手听得懂**的回答。

### 1.2 背景与动机

传统人机对弈中，AI 的选点对新手而言缺乏可理解性——「它又下在莫名其妙的地方」。本模式用两件事补齐：

- **KataGo** 提供围棋决策与量化分析（选点、胜率、目数、归属、变化）。
- **LLM** 把这些量化结果翻译成教学性自然语言，并在对局中与人类「交流」。

### 1.3 设计目标

1. 新手能理解 AI 的每一步。
2. 交流可信：AI 说的每一句关于棋局的话都能追溯到 KataGo 的分析，**不幻觉、不误导**。
3. 对弈流畅：落子不被「讲解」阻塞；讲解慢了也不卡棋。
4. 教学性：回答适应新手水平，能「引导」而非「灌输」。

### 1.4 成功标准（可度量）

- 端到端「AI 落子 → 看到一句解说」体感延迟 ≤ 2~3s，且落子本身 ≤ 1s 完成（解说可稍后到达）。
- 「提问 → 得到回答」p95 ≤ 5s。
- 解说/回答中的每一个坐标、目数、胜率数字都能追溯到一条 KataGo 事实（溯源率 100%，或明确标注「不确定」）。
- 难度调低时，新手有真实胜率（不碾压）。

### 1.5 非目标（本阶段不做）

- 不做 AI 对 AI（自对弈/陪练复盘之外）。
- 不做联网对局、账号系统。
- 不把 LLM 用作决策者或形势判断者（见 §4.1）。

## 2. 术语表

| 术语 | 含义 |
|---|---|
| 分析引擎 / Engine | 提供选点与量化分析的组件，默认指 KataGo，接口上可替换 |
| 语言服务 / ConversationService | 将结构化事实转为自然语言的组件，默认指 LLM，接口上可替换 |
| 事实抽取器 / FactExtractor | 确定性（无 LLM）地把 Analysis 转成 GroundedFacts 的纯函数 |
| GroundedFacts | 可供 LLM 引用、可验证的结构化事实集（防幻觉的事实底稿） |
| Grounding 契约 | 约束 LLM 只能表达 GroundedFacts 内事实的规则 |
| 交流原语 | 本模式提供的六类人机交互（解说/提问/求指点/形势/预警/复盘） |
| 手对 | 人类一手 + AI 一手；人机模式悔棋以「手对」为最小撤销单位 |

## 3. 现状与接缝

### 3.1 现有结构（不修改 `src/go/`）

```
src/go/    规则引擎（无 Qt、无 I/O，可独立单元测试）
  go_types.h   Color / Point / Move
  board.h      纯棋盘数据结构与几何查询
  game.h       完整规则：落子/提子/打劫/终局/计分/悔棋
src/ui/    Qt 桌面界面
  GobanWidget  纯视图，鼠标点击 → pointClicked(x,y)
  MainWindow   持有 Game，onPointClicked 内 game_->play(x,y) 是唯一落子入口
```

### 3.2 改动点（全部集中在 `src/ui/` 与新增 `src/ai/`）

| 现有符号 | 改动 |
|---|---|
| `MainWindow` | 增加模式选择（双人/人机/摆棋）、持有 `AIMatchController`、接入聊天面板 |
| `GobanWidget` | 新增叠加层 setter（ownership / candidates / variation / highlight），仍保持纯视图 |
| `vgo::Game` | **不改**，仍是唯一权威棋盘状态与规则来源 |

### 3.3 关键约束

- `Game` 是同步的、无 I/O 的；引擎分析与 LLM 生成是慢 I/O，必须离开 UI 线程。
- `Game::is_legal()` / `Game::play()` / `Game::undo()` 已覆盖合法性校验与悔棋，AI 落点一律**回 `Game` 复验后再应用**。
- `Game` 的 `snapshot()`（超劫用）与 `score_area()`（数子）可被引擎适配器与解说复用。

## 4. 核心设计

### 4.1 三方职责（边界不可逾越）

| 组件 | 职责 | 绝不做什么 |
|---|---|---|
| `vgo::Game`（现有） | 唯一权威棋盘状态、合法性、提子/打劫/终局 | 不参与决策与解释 |
| KataGo（分析引擎） | 选点、胜率、目数差、每点归属、主变化 | 不产生自然语言 |
| LLM（语言服务） | 把 KataGo 的**结构化事实**翻译成教学性自然语言 | **不选点、不判断形势、不编事实** |

> **LLM 永远不接触「该下哪里」的决策，也永远不单独接触裸棋盘去「自由发挥」。** 它只被允许表达 KataGo 已经算出来的事实。

### 4.2 交流原语（产品层面的「能干什么」）

1. **落子解说（自动）** — AI 每手/关键手后，1~2 句「这手在做什么」。
2. **提问（按需）** — 自由文本，如「你为什么下这里」「这块棋危险吗」。
3. **求指点（教学）** — 「我下一步该走哪」，给候选 + 讲解（可选半提示模式：先引导不直接给答案）。
4. **形势判断** — 「谁领先、领先多少」，用胜率 + 目数 + 通俗比喻。
5. **局中预警（可选开关）** — 人类下出大失误时温和提醒「这一步让你的胜率从 X 掉到 Y」。
6. **终局复盘** — 对局结束后，按关键转折点走一遍叙事。

### 4.3 Grounding（防幻觉）机制 —— 本设计的核心

```
KataGo 原始分析 (Analysis)
        │  确定性「事实抽取器」FactExtractor（纯函数，无 LLM）
        ▼
GroundedFacts（可验证的结构化事实集）
        │  约束性提示词 + 模板骨架
        ▼
LLM 生成自然语言（只允许措辞，不允许新增事实）
```

**Grounding 契约（写死进系统，不靠提示词自觉）：**

1. LLM 输出中每个「坐标 / 目数 / 胜率 / 吃子」必须对应 `GroundedFacts` 里的某条 fact（带 `fact_id`）。
2. 无对应事实时，模板内置诚实条款：「这手的具体意图我需要再算一下才敢说」——**宁可承认不知道，不可编造**。
3. 可选校验器：把 LLM 输出中的数字/坐标抽取出来与 facts 比对，不一致则**回退到纯模板文案**（模板文案本身从 facts 直出，保证可信）。
4. UI 上可 hover 溯源：点某句话 → 高亮它引用的棋盘区域 / 候选点。

## 5. 数据模型

新增类型统一放在 `src/ai/`，与 `src/go/` 同原则：无 Qt、无 I/O。

```cpp
// ---- 引擎输出（KataGo 适配器产出，与具体引擎解耦）----
struct MoveCandidate {
    Point p;            // 候选落点（p 可为 pass）
    double winrate;     // 下这手后的当前方胜率
    double score_lead;  // 下这手后的领先目数（贴目后）
    int    visits;      // 搜索量（置信度/难度标定用）
};

struct OwnershipMap {
    Color  owner(Point p) const;  // size*size，每点归属方
    double points(Point p) const; // 每点目数估计
};

struct Variation { std::vector<Move> moves; };  // 主变化

struct Analysis {
    double winrate, score_lead;
    MoveCandidate best;
    std::vector<MoveCandidate> candidates;
    OwnershipMap ownership;
    Variation principal_variation;
};

// ---- GroundedFacts（事实抽取器产物，LLM 的"事实底稿"）----
enum class FactType { DefendsGroup, CapturesStones, ReducesTerritory,
                      ExpandsTerritory, CreatesEyes, Sente, Gote,
                      BigSwing, SmallSwing };

struct StructuralFact {
    int id;
    FactType type;
    std::vector<Point> region;   // 涉及的棋盘区域
    double delta_points;         // 客观目数差（可为 NA）
};

struct GroundedFacts {
    Analysis analysis;                    // 完整原始分析（供 UI 叠加层）
    std::vector<StructuralFact> facts;    // 抽取出的客观结构事实
};

// ---- 交流侧 ----
enum class QuestionKind { WhyThisMove, WhereToPlay, WhoIsWinning,
                          IsGroupSafe, General, Review };

struct ConversationRequest {
    QuestionKind kind;
    std::string text;            // 用户原始文本
    GroundedFacts facts;         // 当前局面的可信事实（必填，无 facts 则拒绝生成）
    std::string board_context;   // 棋盘/手数可读快照（供 LLM 定位，不作决策依据）
    PlayerProfile profile;       // 等级/人设/教学深度
};

struct ConversationReply {
    std::string text;
    std::vector<int> referenced_fact_ids;   // 溯源
    std::vector<Point> highlight;           // UI 高亮区域
    bool unsure = false;                    // 是否触发"诚实条款"
};

// ---- 模式/会话配置 ----
struct AIModeConfig {
    Color human_color;       // 人类执黑/白
    int strength_level;      // 1~10，映射到 KataGo visits/温度
    CommentaryPolicy policy; // 何时主动讲解（每次/仅关键手/仅失误/关闭）
    PlayerProfile persona;   // 语气、是否引导式、是否给完整答案
};
```

```
  ui/

    GobanWidget.h/.cpp   扩展：ownership 热力、候选点、PV、高亮叠加层
    MainWindow.h/.cpp    扩展：模式选择、接线 controller、聊天 dock
tests/
  test_explain.cpp       事实抽取（构造 Analysis 断言抽取结果）
  test_conversation.cpp  会话接口（EchoConversation 桩，验证契约/溯源）
  test_session.cpp       编排状态机（NullEngine，验证悔棋/取消/异步）
```

### 6.2 关键接口

```cpp
// 引擎侧：KataGo 可替换为任何引擎，测试用 NullEngine（直接返回固定/随机合法点）
class EngineInterface {
public:
    virtual ~EngineInterface() = default;
    // 请求对当前局面做分析；支持取消令牌
    virtual Analysis analyze(const Board& board, Color to_move,
                             const AnalysisParams& p, CancelToken&) = 0;
};

// 交流侧：LLM 可替换，测试用 EchoConversation（把 facts 原样吐出，验证契约）
class ConversationService {
public:
    virtual ~ConversationService() = default;
    virtual ConversationReply answer(const ConversationRequest&) = 0;
};

// 编排：人机对弈的状态机（不依赖 Qt，便于测试；用回调/信号对外）
class AIMatchController {
public:
    void onHumanMove(Point p);                 // 内部调用 game_->play 校验
    void onUserQuestion(const std::string& text);
    void onUndo();                             // 悔一整"手对"，回到人类回合
    void onResign();
    // 异步回调（回到主线程）
    std::function<void(Move, Analysis)> onAiMoveReady;
    std::function<void(ConversationReply)> onReplyReady;
    std::function<void(EngineStatus)> onStatusChanged;  // thinking/explaining/idle
};
```

### 6.3 KataGoAdapter 要点

- 负责 `vgo::Board` ↔ 引擎格式（SGF/GTP）互转。
- 分析参数（visits、温度）到强度等级的映射。
- 分析树缓存：同一局面反复提问不重算。
- 取消支持：新请求/悔棋/换局时作废旧任务。
- **不把棋规交给 KataGo 决定**：引擎给的落点一律回 `game_->is_legal()` 复验；非法（罕见，如引擎不认识的超劫）则回退为虚着或带上劫点重查。

## 7. 关键流程与时序

### 7.1 落子闭环（人类 → AI → 解说）

```
[主线程] 用户点击 → GobanWidget::pointClicked(x,y)
  → MainWindow::onPointClicked → controller.onHumanMove(p)
        → game_->play(p) 成功，刷新棋盘
  → controller 投递"局面快照"到 worker 线程（引擎任务）

[worker]  KataGo analyze（可取消，超时/取消不阻塞）
  → 返回 {最佳点, Analysis}
  → 信号回主线程

[主线程] controller 复验合法性 → game_->play(ai点) → 刷新棋盘（落子立即可见）
  → 按 CommentaryPolicy 决定是否投递"解说任务"（关键手才自动讲解）
  → worker：FactExtractor → GroundedFacts → ConversationService → 回复
  → 流式回 ChatPanel：先出"我下在 D4"，再补"为什么"
```

> **落子与解说解耦**：引擎一给点就先落子（快路径），解说走慢路径（异步、可流式、可取消）。用户不会因为等 LLM 而卡棋。

### 7.2 提问闭环

```
用户输入 → controller.onUserQuestion(text)
  → 若缓存中有当前局面的 Analysis（未过期）则复用，否则触发一次 analyze
  → FactExtractor → GroundedFacts → ConversationService.answer
  → 回复回 ChatPanel，并高亮 referenced 的棋盘区域
```

### 7.3 悔棋语义（与双人模式不同）

- 双人模式 `undo()` 退一手；**人机模式 `undo()` 退一整「手对」**（撤销 AI 上一手 + 人类上一手），回到人类回合。
- 作废所有绑定到「被悔掉局面」的 Analysis 缓存与聊天记录（或标记为历史、不可再溯源）。
- 若 AI 正在思考，`undo` 需先取消当前引擎任务（取消令牌）。

### 7.4 终局复盘

`game_->is_over()` 后：从手数历史中挑出胜率/目数**变化最大的 N 个转折点**（复用或补做 KataGo 分析），LLM 按时间线产出复盘叙事。

## 8. UI / 交互设计

### 8.1 棋盘叠加层（扩展 `GobanWidget`，仍保持纯视图）

新增 setter（不改变「无 Game、只有数据指针」的原则）：

- `setOwnership(const OwnershipMap*)` — 半透明热力图（谁的目）。
- `setCandidates(...)` — 候选点画小圆点（大小 = 置信度/访问量）。
- `setVariation(...)` — 主变化用虚点连线子序列预览（可选显隐）。
- `setHighlight(...)` — 聊天里提到的区域高亮（溯源 hover）。

### 8.2 聊天面板（新增 `ChatPanel`，QDockWidget）

- 消息气泡：人类 / AI；AI 的「解说」与「落子」绑定展示（「D4 — 我补了右上这块棋的断点」）。
- 输入框 + 快捷提问按钮（「我该下哪」「谁领先」），降低新手组织语言成本。
- 每条 AI 回答带「溯源」入口（hover/点击 → 高亮棋盘）。
- 「AI 思考中 / 正在讲解」动画状态。

### 8.3 模式与难度

- 菜单「新局」下分：双人对弈 / 人机对弈（执黑 / 执白）/ 摆棋（沿用）。
- 人机模式侧栏：**难度（1~10）+ 讲解频率 + 语气（引导式/直接式）+ 预警开关**。
- 状态栏增加 AI 侧状态：`思考中… / 正在讲解… / 轮到你`。

## 9. 非功能需求

| 维度 | 要求 |
|---|---|
| 线程模型 | 规则引擎与绘制在 UI 线程；引擎分析与 LLM 生成在 worker；每个「代际」带取消令牌，新请求到来即作废旧请求 |
| 延迟预算 | 落子 ≤1s；解说 ≤3s（关键手）；提问 ≤5s；不达标时先落子、解说标记「稍后补充」 |
| 可测试性 | `ai/` 与 `go/` 一样无 Qt、无 I/O；`EngineInterface`/`ConversationService` 用桩替换；FactExtractor 为纯函数 |
| 降级路径 | LLM 不可用 → 回退纯模板解说（facts 直出）；引擎不可用 → 明示「AI 离线」，回到双人摆棋 |
| 可扩展 | 引擎可换、语言服务可换、语言/人设可换 |

## 10. 难点、风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| LLM 幻觉 | 编造目数/坐标/「它想攻你」 | §4.3 Grounding 契约 + facts 溯源 + 校验回退 + 诚实条款 |
| 「为什么」解释难 | KataGo 只给选点/胜率/主变化，**不给意图**；「为什么」是「结构事实→教学叙事」的映射，最需迭代 | FactExtractor 先抽「防御/提子/围空/先手」等可证明事实；教学叙事只在其上叠加，逐步打磨模板与语料 |
| 延迟叠加 | KataGo 分析 + LLM 生成串起来可能 10s+ | 落子与解说解耦；分析树缓存复用；流式输出；先短答案、细节按需展开 |
| 一致性 | 悔棋/换局后旧分析、旧聊天串到新局面 | 取消令牌 + 按局面快照绑定/作废；控制器是唯一状态机 |
| 难度标定 | KataGo 默认太强，新手无体验 | 强度 = visits + 温度/噪声，注入「像人的失误」 |
| 成本/话痨 | 每手都讲 → 贵且烦 | CommentaryPolicy 只对「关键手 / 大失误 / 提问」主动讲解 |
| 异步竞态 | 快速连点/连问导致乱序 | 单飞（同一时刻只允许一个进行中的引擎任务），其余排队或取消 |

## 11. 分阶段路线

| 阶段 | 内容 | 交付物 |
|---|---|---|
| M0 | 引擎接入：`EngineInterface` + KataGoAdapter + `Analysis` 模型 + `AIMatchController`（无交流） | 跑通「人机对弈 + 难度」，测试用 NullEngine |
| M1 | 事实抽取：`FactExtractor` + `GroundedFacts` + 纯模板解说（无 LLM） | 「防御/提子/围空/形势」四类可信解说 |
| M2 | LLM 交流：`ConversationService` 接入，打通「落子解说 + 提问 + 溯源」 | Grounding 契约与校验回退落地 |
| M3 | 教学增强：求指点/半提示、人设与难度联动、预警开关、终局复盘 | 完整六类交流原语 |
| M4 | 打磨：延迟优化、复盘叙事、多语/人设、语料与模板迭代 | 达标 §1.4 成功标准 |
