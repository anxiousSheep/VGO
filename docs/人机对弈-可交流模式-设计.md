## 1. 概述

### 1.1 定位

桌面围棋练习应用，三种对局模式：

1. **摆棋**：单人自由摆放棋子，同时可向 AI 助手**提问 / 求提示**（AI 不落子）。
2. **人机对弈**：人类执一方、AI 执另一方；AI 落子后**主动解说**，并可用自然语言交流。
3. **本地双人对弈**：黑白双方同一窗口轮流落子（沿用）。

### 1.2 背景与动机

传统人机对弈中 AI 的选点对新手难以理解。本模式用两件事补齐：**KataGo** 提供决策与量化分析，**LLM** 把结果翻译成教学性语言，并在对局/摆棋中与人类「交流」。

### 1.3 设计目标

1. 新手能理解 AI 的每一步。
2. 交流可信：每句关于棋局的话都能追溯到 KataGo 分析，**不幻觉、不误导**。
3. 对弈流畅：落子不被讲解阻塞。
4. 教学性：回答适应新手水平。
5. **对局参数（模式/棋盘大小/执子/难度）在开局时一次性确定，局内不可更改。**
6. **难度体系为 19 级（新手 / 业余 1–9 段 / 职业 1–9 段），按现实棋力排序，且与 KataGo 展示棋力真实对齐。**

### 1.4 成功标准（可度量）

- 「AI 落子 → 看到一句解说」体感 ≤ 2~3s，落子本身 ≤ 1s。
- 「提问 → 回答」p95 ≤ 5s。
- 解说中每个坐标/目数/胜率都可溯源到一条事实（或明确「不确定」）。
- 难度调低时新手有真实胜率。
- 19 个难度标签经基准对局标定，与实际棋力**单调递增**、相邻档有可感知差距（见 §4.4）。

### 1.5 非目标

- 不做 AI 对 AI、联网对局、账号系统。
- 不把 LLM 用作决策者或形势判断者（见 §5.1）。

## 2. 术语表

| 术语 | 含义 |
|---|---|
| 分析引擎 / Engine | 提供选点与量化分析的组件，默认 KataGo，可替换 |
| 语言服务 / ConversationService | 将结构化事实转为自然语言的组件，默认 LLM，可替换 |
| **AI 助手 / AiAdvisor** | 独立的问答/提示组件，**摆棋与人机对弈共用**，见 §7 |

| **humanSLProfile** | KataGo HumanSL 模型的人类段位模仿档位（如 `rank_1d`），覆盖新手~业余高段/职业初段 |

## 4. 对局创建与模式

### 4.1 新对局对话框（⬜）

「新对局」不再是菜单里的一串固定项，而是打开一个**模态对话框**，集中选择对局参数；确定后开始新局。**局内不再提供任何修改这些参数的入口**（菜单/工具栏中的 9/13/19 与难度项移除）。

对话框字段：

| 字段 | 取值 | 说明 |
|---|---|---|
| 模式 | 摆棋 / 人机对弈 | 单选框 |
| 棋盘大小 | 9×9 / 13×13 / 19×19 | 单选框或下拉 |
| 执子（仅人机对弈） | 执黑 / 执白 / **猜先** | 见 §4.3 |
| 难度 | 1~10 | 滑杆/下拉；仅人机对弈有效，摆棋时置灰 |
| 更多设置（可折叠） | 讲解频率、语气（引导式/直接式） | 可选，后续启用 |

按钮：`开始` / `取消`。摆棋模式下「执子」区域隐藏或置灰。

### 4.2 三种模式

| 模式 | 谁落子 | AI 是否落子 | AI 交流是否可用 |
|---|---|---|---|
| 摆棋 | 人类（可摆黑白双方） | 否 | **是**（问答/提示） |
| 人机对弈 | 人类 + AI | 是 | 是（落子解说 + 问答） |
| 本地双人对弈 | 人类双方 | 否 | 否（沿用，可后续放开） |

### 4.3 猜先（nigiri，⬜）

- 人机对弈选择「猜先」时，开局**随机决定谁执黑**（可 50/50，或模拟「抓子猜单双」）。
- 结果在聊天面板与状态栏公布：「猜先结果：你执黑，请先行」。
- 实现上由 `GameSetup` 携带 `nigiri` 标志；创建 `AIMatchController` 前由 UI 随机得出 `human_color` 传入（保持 controller 无随机源、便于测试）。

### 4.4 难度体系（19 级）与 KataGo 对齐

**19 级，按现实棋力从弱到强：**

| 序号 | 段位 | 说明 |
|---|---|---|
| 1 | 新手 | 业余 1 段以下（覆盖整个级位段 30k~1k） |
| 2–10 | 业余 1 段 ~ 业余 9 段 | 9 档 |
| 11–19 | 职业 1 段 ~ 职业 9 段 | 9 档 |

**对齐技术路线（真实性优先）：**

- **新手 + 业余段（1–10）→ HumanSL 模型**（`b18c384nbt-humanv0` + `humanSLProfile`）：档位名即段位（`rank_1d`…`rank_9d`），相对强度可信，无需额外段位标定。
- **职业 1 段（11）**：HumanSL 顶档 `rank_9d`（≈ 职业初段）或标准模型 ~1 visit。
- **职业 2–9 段（12–19）→ 标准模型**（`b18c384nbt`，或 28/40 块）+ 递增搜索预算（visits）。

**真实性声明（必须遵守）：**

1. KataGo 的 HumanSL 模型**只覆盖到约业余 9 段 / 职业初段**，没有职业高段的「人类模仿」档位；职业 2–9 段只能用标准引擎的搜索预算**近似强度**，标签是「相对强度锚点」而非有基准的段位标定。
2. 标准 KataGo 满强度是**超人类**（强于任何人类职业 9 段），故「职业 9 段」是保守下限。
3. HumanSL 档位是 **2 级一档**（…,2k,1d,3d,5d,7d,9d），业余偶数段需在相邻档间插值（search-blend）或取弱档；详见技术路线文档。
4. 所有标签都需经**基准对局标定**后，才能声称与真实棋力对齐。

> 完整 19 级参数映射表与标定步骤见 `docs/技术路线-选型与任务计划.md`。

## 5. 核心设计

### 5.1 三方职责 + AI 助手（边界不可逾越）

| 组件 | 职责 | 绝不做什么 |
|---|---|---|
| `vgo::Game` | 唯一权威棋盘状态、合法性、提子/打劫/终局 | 不参与决策与解释 |
| KataGo（分析引擎） | 选点、胜率、目数差、每点归属、主变化 | 不产生自然语言 |
| LLM（语言服务） | 把 KataGo 的结构化事实翻译成教学性自然语言 | 不选点、不判断形势、不编事实 |
| **AiAdvisor（AI 助手）** | 组合 Engine + ConversationService，对「当前局面」回答问题/给提示 | 不落子、不驱动对局流程 |

> **AiAdvisor 与 AIMatchController 解耦**：人机对弈中由 controller 在 AI 落子后调用 advisor 做解说；摆棋中由 UI 直接调用 advisor 回答问题。两种模式共享同一套「分析 → 事实 → 语言」管线。

### 5.2 交流原语

| 原语 | 说明 | 状态 |
|---|---|---|
| 落子解说（自动） | AI 每手/关键手后 1~2 句 | ✅ |
| 提问（按需） | 「为什么下这里」「这块棋危险吗」等 | ✅ |
| 求指点（教学） | 「我该下哪」→ 候选 + 讲解 | ✅ |
| 形势判断 | 「谁领先」→ 胜率/目数 + 通俗比喻 | ✅ |
| 局中预警（可选） | 人类大失误时温和提醒 | ⬜ |
| 终局复盘 | 终局后按转折点叙事 | ⬜ |

### 5.3 Grounding（防幻觉）机制

```
KataGo 原始分析 (Analysis)
        │  确定性 FactExtractor（纯函数，无 LLM）
        ▼
GroundedFacts（可验证的结构化事实集）
        │  约束性提示词 + 模板骨架
        ▼
LLM 生成自然语言（只允许措辞，不允许新增事实）
```

**契约**：① 输出中的坐标/目数/胜率必须对应某条 fact（带 `fact_id`）；② 无对应事实时模板内置诚实条款「这手的具体意图我需要再算一下才敢说」；③ 可选校验器比对输出与 facts，不一致回退纯模板文案；④ UI 可 hover 溯源。**状态：模板层 ✅，LLM 层 🧪。**

### 5.4 摆棋模式的 AI 响应（⬜）

- 摆棋模式下 AI 不落子，但 AiAdvisor 全程可用：对**当前棋盘局面**回答「谁领先」「我该下哪（提示，高亮候选点）」「为什么（最近一手）」，并可对任意提问给出基于 facts 的回答。
- 「我该下哪」在摆棋中按当前轮到的一方（或用户指定一方）给提示；因无严格行棋方，提示只作参考、不触发落子。

## 6. 数据模型

新增类型统一放在 `src/ai/`（无 Qt、无 I/O）。**状态：数据模型 ✅，`GameSetup` ⬜。**

```cpp
// ---- 对局参数（新对局对话框产出，局内不可变）⬜ ----
enum class GameMode { Placement, HumanVsAi };

struct GameSetup {
    GameMode mode = GameMode::HumanVsAi;
    int size = 9;
    Color human_color = Color::Black;  // nigiri 时由 UI 先随机得出
    bool nigiri = false;
    int level = 1;                     // 1..19，见 §4.4
};

// ---- 强度参数（19 级难度 → 引擎参数）⬜ ----
struct StrengthParams {
    int level = 1;              // 1..19
    std::string human_profile;  // HumanSL 档位（新手+业余段），如 "rank_1d"
    double temperature = 1.0;   // HumanSL 温度
    int max_visits = 1;         // 标准模型搜索预算（职业段）
    double randomness = 0.95;   // 离线 fallback 引擎随机性
};
std::string rankLabel(int level);  // "新手" / "业余3段" / "职业1段"

// ---- 引擎输出（✅）----
struct MoveCandidate { Point p; bool is_pass; double winrate, score_lead; int visits; std::vector<Point> pv; };
struct OwnershipMap { int size; std::vector<double> value; double at(int x,int y) const; };
struct Analysis { bool valid; double winrate, score_lead; MoveCandidate best; std::vector<MoveCandidate> candidates; OwnershipMap ownership; };

// ---- 结构事实（✅）----
enum class FactType { Captures, PutsInAtari, Connects, Extends, Placement, SelfAtari };
struct StructuralFact { FactType type; std::vector<Point> stones; int liberties; };
struct GroundedFacts { Analysis analysis; std::vector<StructuralFact> facts; };

// ---- 交流侧（✅）----
enum class QuestionClass { WhyThisMove, WhereToPlay, WhoIsWinning, Other };
struct PlayerProfile { int level; bool teaching; };
struct ConversationRequest { std::string question; GroundedFacts facts; std::string board_context; double score_black; int move_number; int size; Color to_move; Color last_mover; PlayerProfile profile; };
struct ConversationReply { std::string text; bool unsure; std::vector<Point> highlight; };
```

**AiAdvisor 接口（⬜，由现有 `AIMatchController::ask/currentFacts` 抽取）：**

```cpp
class AiAdvisor {
public:
    using ReplyCb = std::function<void(const ConversationReply&)>;
    // 对给定局面回答问题；提示类问题会查询引擎。
    void ask(const Game& game, const std::string& question, ReplyCb cb);
    // 生成「最近一手」的解说。
    void explainLastMove(const Game& game, ReplyCb cb);
};
```

## 8. 关键流程与时序

### 8.1 新对局（⬜）

```
菜单「对局 → 新对局…」→ NewGameDialog 收集 GameSetup
  → MainWindow 依 setup 创建 Game / AIMatchController / AiAdvisor
  → 若人机对弈且 AI 执黑（含猜先到黑）→ controller.start() 触发 AI 开局
  → 关闭对话框后，参数不可再改（菜单/工具栏无对应入口）
```

### 8.2 人机对弈落子闭环（✅）

```
用户点击 → 合法性校验 → controller.humanPlay
  → engine.requestMove（异步/同步）→ 复验后 game.play(AI 点)
  → onAiMove（聊天显示落点）→ onChanged（刷新棋盘）
  → AiAdvisor.explainLastMove → 解说流式回聊天
```

### 8.3 摆棋 / 提问闭环（摆棋 ✅ 逻辑、UI ⬜）

```
用户在摆棋中摆放棋子 → game.play 成功刷新
用户聊天提问 → AiAdvisor.ask(game, question)
  → 复用或触发一次 analyze → FactExtractor → ConversationService
  → 回复回聊天 + 棋盘高亮
```

### 8.4 悔棋 / 猜先（悔棋 ✅，猜先 ⬜）

- 人机模式悔棋退一整「手对」，回到人类回合；作废被悔局面的分析缓存与聊天记录。
- 猜先在开局一次性随机决定执黑，随后按正常流程进行。
