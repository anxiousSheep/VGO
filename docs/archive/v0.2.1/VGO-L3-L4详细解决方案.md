## 0. 症状根因诊断：为什么「点三三」会下一整个开局

实测现象：让 AI 演示点三三定式，它从空盘下了一整个开局，之后才有概率点三三。这不是模型"不懂定式"这么简单，而是**工具链路上根本没有"定式"这个概念**，三个根因均有代码证据：

### 根因 1：LLM 没有任何定式知识源

`../../../resources/skills` 只有 5 个 stub 包，无定式库；`sgf_lookup_position` 工具只返回**本局手顺**，无定式词典可查。LLM 想把「点三三」映射成坐标序列，只能靠自身常识硬猜——而本地 7B 模型的围棋常识恰恰最弱。

### 根因 2：演示工具只能固定"一手"，无法表达"一条线"

`demonstrate_go_moves` 的参数只有 `point`（单个假设手）+ `plies`（续下手数）。固定一手之后，`collectAiMoves()`（MainWindow.cpp L1532-1551）逐手调 `requestDemoMoveSync()`——**每一手都是 KataGo 按自身policy 自择优**。从空盘出发，KataGo 按布局逻辑走它认为最优的着法，而不是用户点名的定式。LLM 没有任何参数能告诉工具"请逐手摆 C3、D3、E2……这条线"。

### 根因 3：LLM 不知道系统"不会定式"

系统 prompt 里没有定式能力声明，LLM 不知道自己应该承认"我没有定式库"，于是硬答应下，行为自然漂移。

### 本质结论

> VGO 的 harness 哲学是「**LLM 不需要懂棋，只需要可引用、可校验的真值**」（Grounding → Verify-then-Speak）。死活和定式今天的问题，本质是**真值供给层缺了这两块**：没有常型库就没有"刀五、一点就死"的词供给 LLM 引用；没有定式词典就没有"点三三 = C3→D3→…"的线供给工具执行。修复方向不是"让模型学棋"，而是**把常型与定式做成新的真值源**。

## 1. 定式最小闭环（C6 前置，直接治「点三三」症状）

> 范围：不做完整棋谱库位置索引（C6 完整版是数据工程，维持立项），只做"常见定式词典 + 定线演示"最小闭环。**约 1 周，以数据为主，可与 L3-A 并行。**

### 1.2 两个工具变更（根治"下一整个开局"）

1. **新增 `joseki_lookup` 工具**（`agent_tools.cpp` 注册，纯数据查找，同步契约）：
   - 入参：`name`（支持别名模糊匹配）或 `corner`+当前角部局面；
   - 返回：定式序列（含每手注释）、选择建议；
   - system prompt 注入定式**目录**（只有 id+name+aliases 的索引行，几十条很省 token），模型见到「定式/点三三/小飞挂」类提问即调工具。
2. **`demonstrate_go_moves` 增 `sequence` 参数**（string 数组，GTP 坐标）：
   - `handleDemoTool`（MainWindow.cpp L1555）先逐手 `variation_.commitStep` 摆完固定线（复用 `Game probe(b, to_move)` 合法性校验的现有模式，L1543），**再**走 `collectAiMoves(plies)` 引擎续下；
   - LLM 的调用模式变为：`joseki_lookup("点三三")` → 拿到序列 → `demonstrate_go_moves(sequence=[...], plies=0)`；
   - 工具描述补充："当用户点名定式/具体变化时，先用 joseki_lookup 取序列，再用 sequence 逐手演示"。

### 1.3 讲解联动

- LLM 拿到带注释的序列后逐手讲解（每手 `note` 就是 grounding），回答末尾照旧过校验闸门；
- **验收（回归用例）**：空盘问「演示点三三定式」→ 棋盘上逐手摆出词典线 + 逐步注释讲解，不再出现整局开局。
- v2（不在本期）：角部局面→定式名的反向识别（pattern-hash，C6 完整版的子集）。

## 2. L3 · 眼形/要点死活求解 —— 详细方案

### 2.1 目标与非目标（先划边界）

| 目标（做） | 非目标（不做） |
|---|---|
| 识别围合眼位的**死活常型**（直三/曲三/丁四/方四/刀五/花五/花六/板六/直四曲四等） | 不做**通用 tsumego 求解器**（全树搜索是研究级工程，不符合项目体量） |
| 给出**要点**（杀棋点/做活点），回答「为什么做不活」能指到具体点 | 不保证开放局面（无围合眼位）给出常型结论——诚实回落引擎验证或 Unknown |
| 引擎 what-if **验证**结论（Verify-then-Speak 同哲学） | 不做深算路（v1 为 1-ply 双向探测，见 §2.5） |
| 解锁 B6 死活类「要点」档、支撑 L4 题目生成与提示 | 盘角曲四、双活、劫活 v1 只识别为特殊/未决，v2 处理 |

### 2.2 四层架构

```
┌─ L1 眼位提取与假眼识别（纯逻辑，src/ai/lifedeath_shape.h/.cpp）
│     目标棋块 → 围合空点区域 → 真眼/假眼/眼位形状
├─ L2 常型库匹配（纯逻辑，数据驱动，可热更）
│     眼位形状规范化（8 对称 bitmask）→ 常型表 → 状态 + 要点
├─ L3 要点候选排序（纯逻辑）
│     常型要点优先 → 几何启发式（分割势、腰点、二·1）兜底
└─ L4 引擎验证（异步，复用 EnginePool/MoveEvaluator 模式）
      攻方 probe + 守方 probe → 结论分级（常型直判 / 引擎验证 / 未决）
```

### 2.3 L1：眼位提取与假眼识别（纯逻辑）

**眼位区域提取**：给定目标棋块 `G`（`Board::group()` 现成）：

1. 收集 `G` 的所有气与紧邻空点（`Board::liberties()` 现成）；
2. 对每个相邻空点做空点 flood-fill，得连通空区 `R`；
3. **围合判定**：`R` 的边界子全部（或 ≥90%）为 `G` 方颜色 → `R` 是 `G` 的眼位区域；混入少量对方子 → 标记 `contaminated`（可能是吃子后的眼位，降置信）；
4. 棋盘边/角天然围合（无越界邻点要求）。

**假眼识别**（单子眼位专用规则）：单点眼 `p` 为真眼，当且仅当 `p` 的对角邻点中己方控制数达标——**中央 ≥3/4，边上 ≥2/3（在边的方向除外），角上 ≥2/2**。对角含对方子且该子可被立即提掉的，按己方计（提子后成真眼）。

**直判活**（无需引擎）：棋块拥有 ≥2 个单子真眼，或眼位区域匹配为活形（直四/曲四/板六）→ `Alive, verification=PatternOnly`。

### 2.4 L2：常型库（数据驱动）

形状规范化：眼位区域点集 → 平移归一 → bitmask → 8 对称取最小哈希 → 查表。常型表做成**数据文件 + 内嵌双源**（与 skills 完全同构，含 `resources/lifeshapes/*.json` 热更与代码内嵌，规避改表要改代码的问题）：

| 常型 | 眼位点 | 状态 | 要点（杀=做=同点） | 讲解词（供 LLM 引用） |
|---|---|---|---|---|
| 直三 | 3 一线 | 先手死（轮对方走一点即死，轮己方走可活） | 中点 | 「直三，一点正中即死」 |
| 曲三 | 3 拐弯 | 先手死 | 弯中点 | 「曲三，要害在弯处」 |
| 丁四 | 4 丁字 | 先手死 | 丁字中心 | 「丁四，点中心成刀五/曲三杀」 |
| 方四 | 4 方块 | **死形**（己方先走也做不活） | — | 「方四是死形，不用走了」 |
| 直四 | 4 一线 | 活 | — | 「直四是活棋」 |
| 曲四 | 4 拐弯 | 活（角上注意盘角曲四特例，v2） | — | 「曲四是活棋」 |
| 刀五（刀把五） | 5 | 先手死 | 刀把中心 | 「刀五，一点聚杀」 |
| 梅花五（花五） | 5 | 先手死 | 花心 | 「花五，点花心」 |
| 葡萄六（花六） | 6 | 先手死 | 中心 | 「花六，中心是要点」 |
| 板六 | 6 二路线 | 活 | — | 「板六是活棋（角上板六特例 v2）」 |

未知形状 → `Unknown`，不落常型结论，直接进 L3 启发式要点 + L4 引擎验证。

### 2.5 L3：要点候选排序（纯逻辑）

1. **常型命中**：直接用表内要点（杀棋点与做活点在 nakade 类常型中为同一点，双方视角共用）；
2. **未命中启发式**（按优先级）：
   - **分割势最大点**：试占该点后眼位区域被切成两块的点数乘积最大者（近似"把眼位分两半就难活"）；
   - 区域形心（腰带点）；
   - 角部二·1 点（角死活高频要点）；
3. 输出 ≤3 个候选，供引擎验证与提示系统。

### 2.6 L4：引擎验证协议（异步，有界）

复用 `EnginePool::analyzePrioritized`（engine_pool.h L80，Interactive 优先级）与 `MoveEvaluator` 的"棋盘副本试下"模式（注意 evaluate.cpp L107 的教训：**只复制 Board，不复制整局 Game**——收官时 Game 含 ~300KB 历史）。

对目标棋块 `G`（所属方 = 守方，对方 = 攻方）：

```
攻方 probe（≤3 个要点候选 v）:
    副本 Board 上由攻方落 v → analyze → 新 ownership 上 deadGroups() 含 G？
    → 任一 v 成立：记录 kills_at = v
守方 probe（≤3 个守点候选 d，来自要点 + savingCandidates）:
    副本 Board 上由守方落 d → analyze → deadGroups() 不含 G？
    → 任一 d 成立：记录 lives_at = d
```

**结论合成**（与常型直觉完全同构）：

| kills_at | lives_at | 结论 | 对应讲解 |
|---|---|---|---|
| 有 | 有 | **先手死**（Unsettled-先后手相关） | 「对方走 X 你死，你先走 Y 可活——谁先来谁赚」 |
| 有 | 无 | **死**（Dead, EngineVerified） | 「白走 X 即死，且任何防守都救不活」 |
| 无 | 有 | **活**（Alive, EngineVerified） | 「你走 Y 即活」 |
| 无 | 无 | **未决**（Unknown） | 诚实回答「这个局部引擎一时判不清」，不硬答 |

- 常型直判与引擎结论冲突时**以引擎为准**（与校验闸门同哲学），冲突样本落 `bad_samples.jsonl` 反哺常型库修正；
- 劫/双活：v1 不做判定，probe 结果自相矛盾（如杀后死子复活式振荡）时落 `Unsettled` 并标注「疑似劫/特殊型」；
- 降级：无 KataGo → 只出 L1/L2 结论，`verification=PatternOnly`，LLM 侧措辞"按常型判断……（未经验证）"，与降级链纪律一致。

## 3. L4 · 死活题生成与求解 —— 详细方案

### 3.1 题源三路（按优先级）

| 路 | 内容 | 本期 |
|---|---|---|
| ① 内置题库 | **生成器为主、人工精选为辅**：`../../../tools/tsumego_gen.cpp` 用 L3 常型库在角/边摆常型局面，自动生成题面 + 解树，引擎离线验证后入库；另手工精选 20-40 题（古典棋经如《玄玄棋经》为公有领域，但**现代 SGF 汇编有版权风险**，首批以自研生成为主） | ✅ |
| ② 对局挖掘 | 复用恶手采集管线（`maybeWarnBlunder`，MainWindow.cpp L1618+）：对局中某块棋随后死亡时，回溯死亡前局部局面 → 裁切局部 → 引擎验证可杀/可活且解唯一 → 入个人题库（"你自己的死活题"，与 D3.5 每日一题同哲学，教学价值最高） | ✅（Phase C） |
| ③ 引擎合成 | KataGo self-play 批量挖矿 | v2 暂缓 |

### 3.2 题目数据模型（关键决策：JSON，不用 SGF 树）

**决策**：题目用 JSON（`resources/tsumego/*.json` + `board_snapshot` 复用 D3.5 快照格式），**不用 SGF 变分支树**。理由：`parseSgf` 当前只取主变线、跳过变分支（sgf.h 注释明示），扩展 SGF 树解析属 L7 范畴——用 JSON 可避免 L4 被 L7 阻塞；SGF 树导入作为 v2（届时与 L7 一起做）。

```json
{
  "id": "nakade-blade5-01",
  "theme": "nakade",                  // nakade/eye/edge/corner/connect/escape/semeai
  "size": 9,
  "snapshot": ".....XX...",           // Board::snapshot() 格式（复用 boardFromSnapshot）
  "to_move": "black",
  "goal": "kill",                     // kill（做杀方）| live（做活方）
  "target_group": ["D4", "E4", "F4", "E5", "F5"],
  "solution_tree": [
    {"move": "E4", "verdict": "good", "comment": "刀五要点，一点聚杀",
     "children": [
       {"move": "D5", "by": "white", "children": [
         {"move": "C5", "verdict": "good", "comment": "白做不出两眼"}]}]},
    {"move": "D5", "verdict": "bad", "comment": "走错，白 E4 做活",
     "children": [{"move": "E4", "by": "white", "children": []}]}
  ],
  "difficulty": "15k",
  "source": "builtin"
}
```

### 3.3 判题（三层，先树后引擎，诚实兜底）

```cpp
// 纯逻辑（进 CTest）：沿用户已走路径在解树中定位，判定当前手。
enum class TsumegoJudge { Correct, Wrong, OffTree, Solved };
TsumegoJudge judgeTsumegoMove(const TsumegoProblem& p,
                              const std::vector<Move>& path, Move user);
```

1. **树内判题（无需引擎，秒回）**：`good` → 自动从树的 `by:对方` 分支走出应一手（棋盘上即时回应，体验与真人对杀一致）；`bad` → 判负，展示 `comment`；走到叶节点且目标达成 → `Solved`。
2. **树外引擎裁判（异步，Interactive）**：`OffTree` → 副本试下用户手 → KataGo 强档应一手 → 有界交换（≤12 手或目标棋块归属稳定）→ 终态 `deadGroups` 对照 `goal` 判胜负。**歧义/超时诚实回答**「这手棋超出题库变化，引擎也一时判不清」，不硬判。
3. **提示（三级，接 L3 与 B6）**：档 1 方向（「要点在眼位中心一带」，`moveHint` 复用）→ 档 2 要点（**L3 的 `kill_points`/`live_points` 区域高亮，不给精确点**）→ 档 3 答案（演示解树主线）。

### 3.4 UI（新「死活题」标签页，与摆棋/对弈/复盘/每日一题并列）

- **题库浏览**：按主题/难度筛选，每题显示完成状态与最佳成绩；
- **答题棋盘**：限制交互（只能落子，不能悔入真实对局——复用 D3.5 动态重建棋盘模式）；树/引擎自动应手；
- **答案演示**：复用 N2 `VariationController` + `VariationPanel` 逐手走解树（现成的试下状态机，零新增基础设施）；
- **提示按钮**：三档递进（§3.3）；
- **失败重试 / 下一题**流程；每主题统计（尝试/通过率）。

### 3.5 难度标定

- v1：静态标签——按主题 + 解树深度估计（直三=入门 ~18k，刀五/花五=初级 ~12k，角部对杀=中级 ~7k），生成器产出时自动打标；
- v2：用户通过率回流校准（题库统计入 `LearnerStore`，通过率显著高于标称的题降档、反之升档）。

### 3.6 与画像/复习联动

- 答题结果写学习者画像：死活主题失败 → `recordBlunder(BlunderEvent{WeakArea::LifeDeath, severity})` 同源加重；
- 答错的题入复习队列（SM-2 复用 D3 既有实现），隔日重现在「每日一题」队列尾部；
- 隐私开关关闭时不落任何统计（纪律对齐）。

```
定式最小闭环（§1，~1 周，数据为主）── 可立即并行启动，直接治「点三三」
L3-A（2-3 周，纯逻辑）─┬─ 解锁 B6 死活要点档（P2 批的 L3 阻塞解除）
                      ├─ L4-A 依赖（主题分类 + 要点提示 + 生成器）
L3-B（1-2 周）────────┴─ L4-B 依赖（引擎裁判共享 probe 协议）
L4-A（2-3 周）→ L4-B（1-2 周）→ L4-C（持续，依赖 L7）
```

建议把 L4 从 P2 **升格为 P1**（用户实测痛点 + L3 的直接消费者 + 教学闭环的关键拼图）。与 P0/P1/P2 批次的关系：本方案不依赖 A/B/C/D 批次，可独立排期；若 B6（P2 批）先落地，L3 落地时死活要点档自动解锁。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 常型库覆盖度有限（只对围合眼位有效） | 开放局面诚实落 Unknown + 引擎 probe 兜底；呈现永远标 verification 来源，不装懂 |
| ownership 中盘噪声导致 probe 抖动 | 双向 probe 投票；阈值沿用 0.8；冲突落坏样本回收 |
| 盘角曲四/双活/劫误判 | v1 显式识别为特殊/Unsettled，不给死活结论；v2 专项 |
| 引擎裁判成本与延迟 | 有界交换 ≤12 手 + Interactive 优先级 + 并发池；超时诚实降级 |
| 题库版权 | 首批自研生成器 + 公有领域古典题手工重录；不直接搬运现代 SGF 汇编 |
| 定式词典扩张诱发幻觉 | 词典不在库的名字一律回「这个定式我还没收录」，系统 prompt 明示能力边界（治根因 3） |
